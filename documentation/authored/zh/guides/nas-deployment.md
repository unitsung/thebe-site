# 部署到 NAS

Thebe Core v0.1.0 的受支持发布形态是一个容器。把持久数据放在一个目录，把 Agent 可访问的目录限制在单独的工作区。

## 最少需要准备什么

- Docker Engine 与 Compose v2。
- 一个持久化数据目录，用来保存配置、会话元数据、输出和审计记录。
- 一个独立工作区目录，只放入你允许 Agent 读取或修改的文件。
- 一条受保护的管理通道，例如 Tailscale、SSH 隧道或终止 TLS 的反向代理。

## 使用发布镜像

```bash
docker pull ghcr.io/unitsung/thebe-core:0.1.0
```

在 `deploy/.env` 中固定同一个版本标签，不要把 `latest` 当作可回滚的发布版本。工作区和数据目录必须位于同一台宿主机。

## 所有权

容器以 uid/gid `1000` 运行。Linux NAS 上可把工作区交给这个用户；如果文件系统无法设置所有权，改用 Docker 命名卷，或用一个明确的宿主 uid 运行容器。

## 网络

默认只发布 `127.0.0.1:8787`。不要为了“先跑起来”把它改为公网 `0.0.0.0`。远程访问通过 Tailscale、SSH 隧道或反向代理完成，并把公开主机名加入 `THEBE_ALLOWED_HOSTS`。

## 备份

备份时停止容器，复制整个数据目录；恢复时使用同一目录布局。升级失败可以换回上一个镜像标签，但仍使用原数据目录。

完整运行手册见[部署与恢复](/deployment)。
